## 启动

直接双击本目录的 **start_workbench.cmd**。它会启动本机服务并自动打开浏览器：

```text
http://127.0.0.1:8765
```

保留启动窗口，按 `Ctrl+C` 可关闭。若浏览器未自动打开，复制上述地址访问。

重复双击时会识别并复用同目录、同运行目录的新版服务，不会重复监听端口。更新代码后若仍有旧服务运行，页面会显示明确的旧版提示；关闭旧启动窗口后再启动。Windows端口采用独占监听，第二次启动不会修改正在运行的任务状态。

也可以在命令提示符中运行：

```cmd
python run_workbench.py
```

端口被占用时：

```cmd
python run_workbench.py --port 8766
```

工作台本身只使用 Python 3.11+ 标准库，无需安装网页框架或 Node.js。两个 Agent 继续使用原来的依赖环境；默认复用发布评审项目的 `.venv` Python 运行子任务，该环境也需要旧项目要求的 PyYAML。

## 页面怎么用

| 页面 | 操作 |
|---|---|
| 总览 | 查看任务状态，选择诊断或评审入口 |
| 故障诊断 | 默认“完整订单故障演示”，资料和时间窗已配好，点击开始诊断 |
| 发布评审 | 默认“完整正常发布演示”，点击开始评审，然后手动提交阅读意见 |
| 任务与报告 | 查看进度、日志、报告、证据、模型用量，下载 Markdown 或 JSON |

## 输入自己的材料

“材料来源”选择“自己输入材料”，填写服务、环境、时间和问题；发布评审另填变更编号。名称支持1至80个英文字母、数字、下划线和连字符，包括自定义服务和环境。

- **简易表单**：直接粘贴日志、指标、链路、变更，或填写发布目的、代码说明、检查状态、容量和计划。只填已知信息，不知道的数字留空。
- **JSON材料 / 文件导入**：粘贴标准JSON，或选择本机JSON文件。可先点击“载入此场景材料并编辑”查看完整结构；原示例不会被修改。
- **修改示例范围**：仅对明确标注的模拟材料提供“将演示材料绑定到当前范围”。这只重命名模拟范围，不会采集真实数据。用户资料须自己保证JSON范围与表单一致。

指标简式每行 `指标名=数值 单位`，例如 `request_error_rate=0.01 ratio`、`request_latency_p95=200 ms`。链路简式为 `GET /orders|ok|180|app.handle:160`。日志与变更可逐行粘贴原文。简式记录使用明确填写的材料观测时间；多时间点和完整配置差异用JSON保留。

发布容量填写副本数、单副本连接池上限、数据库总连接上限和其他消费者连接数，系统按这些输入计算目标需求与余量；不自动访问数据库。检查结果选择“未知”或数字留空时，会保留真实缺项。自填材料最多512KiB、500条记录。

资料来源分为“模拟演示”与“用户提供（未经核实）”。选择真实模型才发送API请求；输入production等环境名仍然只读本地资料，不会连接生产或执行变更。

## 删除与恢复报告

在“任务与报告”选择记录，点击“移到回收站”；切换左侧“回收站”可预览并“恢复报告”。删除采用可恢复方式，报告文件、原业务状态和人工意见保留，历史扫描与重启不会自动把它恢复到任务列表。

排队或运行中的任务暂不能移入回收站。待人工复核的报告移入后不能提交意见，恢复后须继续按原材料指纹复核。回收站不提供永久清除；这里用于整理报告，不删除Agent的记忆数据库。

默认选中 **离线演示**，不调用模型 API。选择 **真实模型** 才调用已有模型配置；接口密钥继续保存在各 Agent 原来的配置中，网页不要求填写或展示密钥。

发布评审结束自动暂停。请先阅读报告，再填写姓名、意见和备注，点击提交。`确认已阅读`、`要求修改`、`拒绝报告` 均不是批准上线；容量阻断和质量问题不会因为点击确认而消失。

新增的完整资料包在两个项目各自的 `data/demo_complete/` 中。`safe` 解释发布目的、版本变化、配置保持不变的原因，并附演示负责人、回退和验证计划；`risk-pool` 展示容量阻断；`missing` 故意保留缺项。原始资料包独立保留，网页可另行选择。

预检显示指标、日志等**类别是否覆盖**，并不证明证据充分。时间窗没有任何当前记录时，会在启动模型前拒绝提交。“预发布正常片段”只有两条观测，会提示补查，也不会生成无关的连接池修复建议。完整故障演示补充了模拟流量、连接归还、数据库容量和配置资料，避免因演示输入缺省而反复追问。

离线评审会预填测试署名“演示评审员”，仍需手动提交；真实模型评审须填写本人署名。资料中的演示负责人是虚构角色，回退和验证仍是未执行计划。

## 自动查找与路径配置

默认查找：

- 故障诊断：优先本工作台旁的修复版 `it_ops_agent_fixed_v1_2`；没有时查找 `D:/Project/agent/it_ops_agent` 或旁边的 `it_ops_agent`。
- 新项目：本工作台旁边的 `release_risk_agent`。
- 子任务 Python：优先新项目中的 `.venv/Scripts/python.exe`，否则使用启动工作台的 Python。

路径不同，可将 `workbench.config.example.json` 复制为 `workbench.config.json` 并修改。相对路径以该配置文件所在目录为基准。也可分别设置 `ops_python` 和 `release_python` 指向不同虚拟环境。

配置仅填写项目/解释器/运行目录路径，不填写密钥。`OPS_AGENT_PROJECT`、`RELEASE_AGENT_PROJECT`、`WORKBENCH_PYTHON` 环境变量也可覆盖路径。

本机存在 D 盘旧项目时，工作台用 `OPS_SETTINGS_FILE` 在运行时复用其已有模型配置，历史报告也从原目录只读索引。不会复制密钥或修改 D 盘源码。可在可信的 `workbench.config.json` 中用 `ops_settings_file`、`ops_history_project` 指定其他绝对路径。网页不能设置这些路径。发布项目继续使用自己的原配置。

更新过代码后，关闭旧启动窗口并重新双击启动，再刷新浏览器。旧任务仍展示原报告；选择完整场景新建任务才能看到此次修复结果。

## 数据保存位置

- 工作台任务和有界日志：`runtime/workbench.sqlite3`。
- 每个新任务使用独立演示输入快照：`runtime/inputs/<任务编号>/`，后续修改原资料不会改变排队任务或已生成报告。
- 从网页新建的旧项目诊断报告和记忆：`runtime/ops/`，不向 D 盘旧项目写入。
- 发布评审：继续使用发布项目的 `runtime/`，可以在网页查看既有报告并对仍在等待的评审提交本人意见。
- 已有旧项目 `runtime/reports/` 的报告会只读列入历史。

服务重启时，尚在排队或执行的任务会标为中断，不会自动重新发送收费模型请求。已生成的报告仍可查看。若远端请求已经收到但本地被中断，是否计费仍以模型服务记录为准。

## 实现与边界

浏览器使用原生 HTML、CSS、JavaScript；本机 Python HTTP 服务提供任务接口，SQLite 保存任务，最多两个后台任务并行。两个 Agent 通过固定参数的子进程调用，原来的 CLI、模型逻辑、MCP、LangGraph 和规则检查继续生效。

服务只绑定本机回环地址，写请求检查页面会话令牌和来源。报告按内部任务编号读取，不能通过网页输入任意文件路径或系统命令。材料内容只作为数据处理，不执行其中的代码或地址；报告按文本和受限格式展示。本版面向同一台电脑的本地使用，不包含企业登录、多用户权限或远程服务部署。

工作台没有发布、回滚或任意命令执行按钮。旧项目的案例确认和训练数据导出、Redis 队列管理仍保留在原 CLI 中；本版网页覆盖日常诊断、直接评审、人工意见与报告查询。
